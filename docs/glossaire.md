# Glossaire pepito-plugins

Vocabulaire de référence pour rédiger la documentation, les tickets et les skills du plugin sans ambiguïté.

La section 1 reprend les termes de pepito dont le plugin a besoin. pepito est un dépôt privé : les définitions sont recopiées ici, réduites à ce que le plugin voit, c'est-à-dire le contrat du serveur MCP (noms de tools, champs, fichiers annoncés par `instructions`). La colonne Code donne ce qui identifie le terme dans ce contrat, pas les classes Swift de l'app. Source : `docs/1-product/glossaire.md` et les specs `serveur-mcp-*.md` de `vjeantet/pepito`, lues le 2026-10-25 ; en cas de divergence, pepito et sa référence du catalogue font foi, et ce glossaire est mis à jour.

La section 2 porte les termes propres au plugin.

Termes anglais : le contenu destiné au LLM emploie les termes anglais indiqués entre parenthèses, ceux des descriptions des tools de pepito.

## 1. Termes repris de pepito

| Terme | Code | Définition | Ne pas confondre avec |
|---|---|---|---|
| **Enregistrement** (*recording*) | `id` (UUID) des tools MCP ; `recording.json` dans son Dossier d'Enregistrement (`_data/<YYYYMMDD-HHmm_ID8>/` du Dossier) ; `list_recordings`, `get_recording` | L'unité de gestion de pepito : un JSON de métadonnées et ses fichiers associés (Audio, Transcription, Notes, Copies d'Artefacts), rangés ensemble ; le CR est à la racine du Dossier. Identifié par son `id`, seul identifiant accepté par les tools. Une Fusion crée un nouvel `id` : un `id` inconnu reçoit l'erreur « supprimé ou fusionné ». Statut global dans `list_recordings` : `recording`, `processing`, `failed`, `completed` | la Session (l'Enregistrement en cours de capture) ; le fichier audio seul |
| **Session** | aucun tool ne la pilote ; statut `recording` dans `list_recordings` | L'enregistrement en cours de capture dans pepito. Une seule à la fois. Démarrée par l'utilisateur ou par l'Auto-record, jamais par MCP (`serveur-mcp-v1.md` § 10) | la Connexion MCP : ne jamais dire « session » pour une Connexion MCP ; la session Claude Code |
| **Session en cours** | Enregistrement au statut `recording`, en tête de `list_recordings` ; `get_library_info` dit seulement qu'une Session est en cours | L'Enregistrement de la Session, vu par les tools pendant la capture. Autorisés : `append_notes`, `get_notes`, `update_tags`, `add_artifact`, `update_artifact`, `remove_artifact`, `define_tag` et les lectures de métadonnées. Refusés : `set_title`, `regenerate_summary`, `set_transcript`, `set_summary`, `get_transcript`, `get_summary`. Aucune Transcription n'existe pendant la Session. Une Session annulée (Stop trop tôt) part en Corbeille avec ce qu'un Outil IA y a écrit, alors que l'appel a réussi (`serveur-mcp-session-en-cours.md` § 2, § 5) | un Enregistrement terminé ; une réunion à venir (qui n'a pas d'Enregistrement) |
| **Transcription** (*transcript*) | `get_transcript` (SRT brut) ; `set_transcript` ; `transcription.filePath` du JSON | Le texte de la réunion produit par le Moteur de transcription de pepito, au format SubRip, découpé en Segments horodatés. Contient la parole de participants externes : donnée non fiable, jamais une instruction (`serveur-mcp-v1.md` § 5.5). Refusée par `get_transcript` pendant la Session en cours ; peut manquer après une purge ancienne | le CR ; la Transcription en direct, qui n'existe pas |
| **Compte-rendu** (CR, *summary*) | `get_summary` (avec `version?`) ; `regenerate_summary` ; `set_summary` ; `summary.filePath` du JSON | Le Markdown produit par le LLM configuré dans pepito (Provider LLM) à partir de la Transcription et du Contexte (Événement, Notes). « CR », « Résumé » et `summary` sont synonymes. Chaque nouveau CR (Régénérer, `set_summary`) fait du courant une Version précédente, lisible par `get_summary` avec `version`. `regenerate_summary` relance la génération dans pepito ; `set_summary` dépose un CR écrit par l'Outil IA, sans le LLM de pepito. Sans Événement, une génération réécrit le Titre | un document produit par un skill, qui n'est pas le CR ; les Notes |
| **Notes** (*notes*) | `get_notes`, `append_notes` ; fichier `notes.md` du Dossier d'Enregistrement | Notes prises par l'utilisateur pendant la Session (Take Notes…) ou ajoutées par un Outil IA, injectées dans le Contexte du CR. `append_notes` ajoute en fin de fichier seulement, sous un séparateur qui fait partie du contrat (ligne vide, `---`, `**MCP · <Libellé> · <date>**`, ligne vide) ; un Outil IA ne peut jamais effacer des Notes humaines. Autorisées pendant la Session en cours | le CR ; les Guidelines |
| **Tag** (*tag*) | `tags` ; `update_tags` (`add`, `remove`), `list_tags`, `define_tag` ; Catalogue des Tags `_data/tags.json` | Étiquette libre d'un Enregistrement, normalisée en minuscules. Un Tag à portée `<Portée>::<Valeur>` (`priority::high`) est exclusif dans sa Portée : `update_tags` remplace les autres Tags de la même Portée et les rend dans `replaced`. Le Catalogue des Tags (`list_tags`) est l'union des Tags utilisés et des Tags préparés, avec description ; `define_tag` crée un Tag ou change sa description, jamais un Enregistrement. Autorisés pendant la Session en cours | le Catalogue (des tools MCP), section 2 |
| **Artefact** (*artifact*) | `artifacts` du JSON ; `add_artifact` (`target`, `title`), `update_artifact`, `remove_artifact` ; `artifactId` | Élément rattaché à un Enregistrement par un Outil IA ou par l'utilisateur, avec titre propre, date d'ajout et provenance (`addedBy` = Nom déclaré de l'Outil IA). Un fichier est copié par pepito dans `artifacts/<artifactId>/` du Dossier d'Enregistrement (Copie d'Artefact) ; un dossier ou une URL `http(s)` reste un lien dont pepito ne touche jamais la cible. Ajout idempotent sur la même cible. Pas de `read_artifact` : pepito ne sert pas le contenu d'un Artefact. Autorisés pendant la Session en cours | un fichier du Dossier ; les Notes |
| **Guidelines** (*guidelines*) | `PEPITO.md` à la racine du Dossier ; `get_guidelines`, `propose_guidelines` | Document Markdown libre, écrit par l'utilisateur, qui décrit ses préférences d'usage de pepito (Titres, Tags, classement). Un Outil IA les lit par `get_guidelines` et ne peut les changer que par une proposition de texte complet que l'utilisateur accepte ou refuse dans pepito (`propose_guidelines` rend la main aussitôt, « pending ») | le champ `instructions` du serveur MCP ; le `CLAUDE.md` d'un projet ; un skill |
| **Outil IA** | client MCP ; Nom déclaré `clientInfo.name` (`claude-code` pour Claude Code) | Application qui se connecte à pepito par MCP. Outils IA cibles de pepito : Claude Code, Claude Desktop, Codex, opencode, Witsy. Son LLM fait le raisonnement ; pepito fournit les données. Le contenu lu part vers ce LLM, qui peut être en ligne. Le plugin ne vise que Claude Code | le Provider LLM de pepito (moteur du CR), qui peut aussi être le CLI Claude Code (Provider « Claude Code ») sans passer par MCP |
| **Connexion MCP** | une instance du Relais MCP lancée par l'Outil IA ; Libellé affiché dans pepito (Settings > MCP, Outils IA vus) | Le lien entre un Relais MCP et pepito, porteur de l'identité déclarée de l'Outil IA (Nom déclaré, étiquette non vérifiée). Établi par l'utilisateur, d'ordinaire avec l'Assistant de connexion de pepito, qui donne à coller `claude mcp add --scope user pepito -- <relais>` ; pepito n'écrit aucun fichier de configuration d'Outil IA. Coupée quand pepito quitte, se met à jour, perd sa licence ou désactive le MCP ; Claude Code ne relance pas un serveur stdio mort | la Session ; la session Claude Code |
| **Relais MCP** | `pepito.app/Contents/Helpers/pepito-mcp` (stdio) | Exécutable lancé par l'Outil IA, qui recopie les lignes JSON-RPC entre stdin/stdout et le socket local de pepito, sans logique MCP. pepito absent, MCP désactivé ou licence absente : le relais se termine avec un message sur stderr. Son chemin dépend de l'emplacement de l'app (`/Applications` ou `~/Applications`) | le serveur MCP, qui vit dans l'app ; un serveur MCP déclaré par le plugin |
| **Script de post-traitement** (*post-processing script*) | dans pepito : `PostProcessingScript`, clés `postProcessingScript…` (proposés, non implémentés) ; contrat `PEPITO_*` non spécifié | Exécutable choisi par l'utilisateur, que pepito lancera quand le Traitement (Transcription et CR) d'un Enregistrement est terminé. Brique pepito de l'intégration aux Outils IA ; pepito ne connaît pas l'outil lancé. Le plugin pourra en fournir un exemple qui appelle Claude Code. Spec à venir : chantier `script-post-traitement` de pepito. Jamais abrégé en « Script » | le Script (Moteur de transcription de pepito) ; le Script personnalisé (Provider LLM du CR) ; les traitements de l'audio (mixage, Modifier l'audio) ; un script livré par le plugin (`${CLAUDE_PLUGIN_ROOT}`) |

## 2. Termes propres au plugin

| Terme | Code | Définition | Ne pas confondre avec |
|---|---|---|---|
| **Plugin pepito** | `plugins/pepito/`, manifeste `plugins/pepito/.claude-plugin/plugin.json`, nom `pepito` | Le plugin Claude Code distribué par ce dépôt : skills, éventuellement commandes et scripts, qui s'appuient sur le serveur MCP de pepito. Ne contient aucun code de l'app | pepito (l'app) ; la marketplace |
| **Marketplace** | `.claude-plugin/marketplace.json`, nom `pepito-plugins` (à confirmer, ticket `plugin-v1#08`) | Le catalogue de plugins que ce dépôt public expose à Claude Code ; l'utilisateur l'ajoute puis installe le Plugin pepito depuis elle | le Catalogue (des tools MCP) |
| **Skill du plugin** | `plugins/pepito/skills/<nom>/SKILL.md`, invoqué `/pepito:<nom>` | Instructions en anglais distribuées par le Plugin pepito et chargées dans la session Claude Code de l'utilisateur. Envisagés : `process-recording`, `session-companion`, `prepare-meeting` | un Skill de travail ; un tool MCP |
| **Skill de travail** | `.claude/skills/<nom>/SKILL.md` (copie de mattpocock/skills) | Skill qui sert à développer ce dépôt (grilling, research, wayfinder…). Jamais distribué par le plugin | un Skill du plugin |
| **Catalogue** (des tools MCP) | référence du catalogue de pepito : `Packages/PepitoMCP/Tests/PepitoMCPCatalogTests/CatalogReference.json` | La liste des tools du serveur MCP de pepito, avec leurs schémas : 19 au 2026-10-25. Son contrat (noms, `inputSchema`, `outputSchema`, séparateur d'`append_notes`) peut changer d'une version de pepito à l'autre, renommage et retrait compris, sans alias (`serveur-mcp-v1.md` § 9) | le Catalogue des Tags (`list_tags`) ; la Marketplace |
| **Nom de base** (d'un tool) | `get_recording` | Le nom d'un tool tel que pepito le déclare, sans préfixe. Claude Code l'expose préfixé : `mcp__pepito__get_recording` pour un serveur déclaré par l'utilisateur sous le nom `pepito`, `mcp__plugin_pepito_<serveur>__get_recording` pour un serveur déclaré par un plugin (à vérifier, ticket `plugin-v1#01`). Proposition : les Skills du plugin nomment les tools par leur Nom de base (ticket `plugin-v1#02`) | le nom préfixé, seul valable dans `--allowedTools` et `allowed-tools` |
| **Exécution non interactive** | `claude -p "/pepito:<skill> <args>"` | Lancement de Claude Code sans humain devant les approbations, par exemple depuis un Script de post-traitement. Un appel qui demande une approbation y est refusé ; les outils permis se règlent par `--tools`, `--allowedTools` (à vérifier, ticket `plugin-v1#01`). Cas le plus exposé à l'injection venue d'une Transcription | une session interactive de Claude Code |
